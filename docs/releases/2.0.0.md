# @astro-notion/loader 2.0.0

Version 2.0.0 updates the loader for Astro 6 and 7 and the current Notion data-source API. Existing `1.1.2` users should follow the [2.0 migration guide](../migrations/2.0.md) before upgrading.

## Breaking Changes

- Node.js `>=22.13.0` is required. Node.js 18 is no longer supported.
- Astro `>=6 <8` is required. Astro 5 is no longer supported.
- The package is now published as `@astro-notion/loader`; imports from `@chlorinec-pkgs/notion-astro-loader` must be replaced.
- Loader configuration now requires `data_source_id` and queries `Client.dataSources`. The former `database_id` option and deprecated database query API are no longer supported.
- Automatic collection schemas use Astro's dynamic `createSchema()` loader contract and are generated from the selected data source's properties.

## Added

- Astro 7 support alongside Astro 6, with the same loader configuration and public exports on both versions.
- Hosted document, PDF, video, and audio downloads through the configurable `publicPath` destination.
- Base-path-aware URLs for downloaded public assets.
- Public Notion SDK-derived page, block, property, and asset types from the main package export.
- The current Notion `in_trash` query option. The deprecated `archived` option remains accepted for compatibility and is translated to `in_trash` when the current option is not supplied.
- Stable `cacheImageInData` and `rootSourceAlias` options for page-data asset caching and transformed cover-image paths.

## Changed

- Notion-hosted page-content images are stored below `src/<imageSavePath>` for Astro image processing, while hosted documents and media are stored below `publicPath` for direct serving.
- External asset URLs remain remote instead of being downloaded.
- Hosted covers, icons, and file properties can use the same split destinations when `cacheImageInData` is enabled.
- The deprecated `experimentalCacheImageInData` and `experimentalRootSourceAlias` aliases remain accepted for one major. When both a canonical option and its alias are supplied, the canonical option wins; an effective alias emits a deprecation warning.
- Page rendering now uses `@astro-notion/notion-rehype` and emits Astro-compatible image metadata for content entries.
- The loader validates that a configured `publicPath` remains inside Astro's `publicDir`.

## Fixed

- Concurrent page renders no longer share heading state, preventing one entry from receiving another entry's table-of-contents metadata.
- A failed render no longer updates the cached digest, so a later content sync retries the page instead of treating incomplete output as current.
- A failed page render now rejects the content sync instead of caching incomplete output, so failures surface as a failed sync rather than silently stale content.
- Notion property schemas and formatters align with Astro 6 and 7's Zod contract, including nullable and transformed property values.
- Hosted files in file, PDF, video, audio, image, callout, cover, icon, and page-property positions are handled consistently.

For ordered configuration changes and verification steps, see [Migrating from 1.1.2 to 2.0.0](../migrations/2.0.md).
